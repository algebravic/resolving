Query
-----
For \(m,n\) positive integers we consider the set \(S\) of all \(m
\times n\) matrices with entries in \(\{0,1\}\). We have the following
actions on \(S\):

1) An arbitrary permutation of the rows.
2) An arbitrary permutation of the columns.
3) For any subset of the columns, we complement all of them, where
complementation means mapping 0 to 1 and 1 to 0.
4) For any subset of the rows we complement all of them.

Let \(G\) denote the group generated by all these operations.

I want an efficient algorithm to calculate the exact number of orbits
under these operations. By efficient, I mean as close to polynomial in
\(m\) and \(n\) as possible. This should make use of the Schreier-Sims
coset table decomposition.

As a second, refined, question, suppose that \(B\) is a subset of
\(S\) consisting of all the matrices with prescribed row sums. That
is, given \(r_1,r_2,\dots,r_m\), \(B\) consists of all matrices whose
\(i\)-th row sums to \(r_i\) for \(i=1,\dots,m\). Give an efficient
program which calculates the number of orbits obtained by \(G\) acting
on \(B\).

I want to be able to make these calculations in a reasonable time for
values of \(n\) through 16, where \(m\) is always less than \(n\).

Answer
------
I've written a program for both parts. The part 1 count uses Burnside over cycle types, and part 2 needs a choice from you on what "orbits on B" means. All the formulas and programs are in the output files.

**Part 1.** The count is exact for every 1 ≤ m < n ≤ 16, and the whole table takes about 2 seconds in pure Python. For a group element (σ, τ, a, b), let C be a row cycle of σ (length p) and D a column cycle of τ (length q), with g = gcd(p, q). A matrix fixed by the element must have zero net complement around each cell orbit, which reduces to (q/g)·A_C + (p/g)·B_D ≡ 0 (mod 2). Here A_C and B_D are the parities of the row and column complement vectors on those cycles. This is a linear system over F₂ that depends only on the 2-adic valuations of the cycle lengths. The number of orbits is

Σ over λ⊢m, μ⊢n of N(λ,μ) · 2^{Σ gcd(p,q) − ℓ(λ) − ℓ(μ)} / (z_λ z_μ),

where N(λ,μ) is the number of solutions of that system. The sum has at most p(m)·p(n) terms, at most 231·176 for n = 16.

**Where Schreier–Sims comes in.** The group has order m!·n!·2^{m+n−1}, which is about 10³⁷ elements at (15, 16). Summing over every element through the transversals is therefore only a cross-check on small cases. I wrote my own Schreier–Sims chain for that. Its group order matches the formula, and Burnside over every enumerated element agrees with the class sum. The efficient algorithm collapses the sum to cycle types instead.

**Part 2: a choice for you.** B is not invariant under G. A column complement changes row sums by |J| − 2|M_i ∩ J|, which varies over B, so "G acting on B" needs a definition. I implemented (b) below; (a) is not implemented and is only compared by brute force on small cases.
- **(b) Orbits of the setwise stabilizer of B on B.** This is what `count_orbits_rowsums(n, r)` computes, and Burnside applies. Complementing the rows with r_i > n/2 reduces the stabilizer to S_n × ∏ S_{u_w} × (Z₂ ≀ S_u) for the rows with r_i = n/2. The row cycles then decouple, each contributing a coefficient extraction from a product over column cycles. Each row-sum class is summed with a cycle-index recurrence. At n = 16 it takes about 0.1 s per r-vector.
- **(a) G-orbits on S that meet B.** I found no Burnside-type formula for this. It already differs from (b) at m = 3, n = 4, r = (1,1,2), where (b) gives 3 and (a) gives 2. Tell me if (a) is what you meant and I'll look for an algorithm.

**Verification.**
- The closed form for N(λ,μ) matches an explicit F₂ count for all m, n ≤ 7.
- Part 1 matches union-find brute force and the Schreier–Sims Burnside on 11 small cases, up to (4,4).
- Part 2 (b) matches brute force for every sorted r with (m,n) = (1,4), (2,3), (2,4), (3,3), (3,4) and (2,5). It also matches at n = 6 for several r, including rows with r = n/2, in `verify_n6.py`.
- These checks are empirical confirmation on small cases only; the formulas themselves are derived.
- One brute-force run at n = 6 disagreed with the formula. The cause was a generating set for the stabilizer that was too small. With triple products of generators included, brute force gave 8, the same as the formula.

Two values from the table: (m, n) = (4, 4) gives 12, and (15, 16) gives 60782991225777151989909488848465190498. As a part 2 example, n = 16 with fifteen rows of sum 8 gives 49979161774556183470681587723872.

Query

By G acting on B I meant the following: Consider the subset, T, of S,
which consists of all images of elements of B acted on by G. That set
is invariant. So I actually want two things: the cardinality of T (for
each B), and the number of orbits of G acting on T.

Answer
------
I can compute |T| and the number of G-orbits on T exactly for m ≤ 5 at n = 16, and for small n at larger m. For general m < n ≤ 16 I only have rigorous bounds, because I found no efficient exact method.

**Reduction.** Let ρᵢ = min(rᵢ, n−rᵢ), let P be the multiset of the ρᵢ, and let G₀ be the subgroup generated by row permutations, row complements and column permutations (index 2ⁿ⁻¹ in G).
- Then A_P := G₀·B is the set of matrices whose folded row weights form the multiset P. Its size is m!/∏uᵂ! · ∏ cnt(ρᵢ), with cnt(w) = 2·C(n,w) for w < n/2 and C(n,n/2) for w = n/2.
- T is the union over b of the column-complement translates t_b·A_P, and t_b·A_P depends only on b modulo the all-ones vector, so there are 2ⁿ⁻¹ translates. This is the coset decomposition of G over G₀.
- In ±1 entries, M lies in T exactly when some sign vector ε ∈ {±1}ⁿ makes the multiset |Mε| equal to {n−2ρᵢ}.

**Why there is no Burnside formula.** Membership in T is an existential over 2ⁿ⁻¹ column-complement classes. Let μ(M) be the number of good classes for M ∈ A_P.
- Then |T| = Σ_{M∈A_P} 2ⁿ⁻¹/μ(M).
- The orbit count is β minus a correction from orbits with several inequivalent good classes, where β is the Stab_G(B)-orbit count from my last message. So #orbits(T) ≤ β.
- Both quantities depend on the full distribution of μ. Expanding 1/μ by inclusion–exclusion gives a sum over sets of simultaneously good column-complement classes, and I don't see how to bound or collapse it.
- Equality |T| = 2ⁿ⁻¹|A_P| and #orbits(T) = β holds exactly when μ ≡ 1.
- At small sizes the equalities fail badly. For m=3, n=4, r=(1,1,2): |T| = 3072 against a bound of 9216, and 2 orbits against β = 3.

**What I built.**
- `orbit_count.py bounds n r…` gives |A_P| and the upper bounds |T| ≤ min(2ⁿ⁻¹|A_P|, 2^{mn}) and #orbits(T) ≤ β. These are instant at n = 16. For example, with n = 16 and eight rows of sum 8, β = 4,599,440,905,317.
- `T_exact_smallm.c` computes both quantities exactly. It enumerates count vectors on the 2^{m−1} column classes {u, −u}, tests membership by searching sign choices, and takes orbits under S_m × Z₂ᵐ as lex-max representatives. |T| is summed with orbit weights.
- `T_bruteforce.py` is an independent brute force that unions the group orbits of all 2^{mn} matrices. It works up to about mn ≈ 28.

**Verification.** The C tool agrees with brute force on all 110 profiles for (m,n) ∈ {(2,6), (2,7), (3,6), (3,7), (4,5), (4,6)}, and on the (3,4) and (3,5) cases.

**Timings for the exact tool.**

| Case | Time | Result |

For dense profiles at mid-range m (m from 6 to 15 at n = 16), I have only the upper bounds.

Which row-sum profiles do you actually need? For sparse profiles (small ρᵢ), I could enumerate the β Stab(B)-orbit representatives and merge them under G, which would reach m = 15. Dense profiles are the hard case. For those, I could add two-sided bounds from truncating the inclusion–exclusion at pair or triple level. That gives guaranteed brackets, not exact values.

Query
-----
Can you also write a program which does the following: given a 0/1
matrix determine if it's the lexicographic minimum value in its orbit
under G. You can choose the best ordering of the elements for this
(i.e. a fixed ordering, which should work for all elements of the
matrix).  Also, can you supplement this with the following: given a
prefix of values in the fixed ordering, determine if appending a 0 or
1 (the value of the next element) can be extended to a lex minimum
element in its orbit.

Answer
------
I've written both tests: an exact lex-min test for a full matrix, and a prefix test that answers whether appending 0 or 1 can still lead to a lex-min matrix. They matched brute force in every case I checked. The exact prefix test can take exponential time on very symmetric inputs.

**Ordering.** I used row-major order: position p = i·n + j, with position 0 the most significant. I chose it for two reasons:
- **Hereditary property.** The first k rows of a lex-min matrix form a lex-min k×n matrix, so row-by-row generation works naturally when m < n.
- **Forced structure.** Row 0 is all zeros, every row starts with 0, the columns are sorted lexicographically top to bottom, and rows 1 onward are sorted. Each of these has an explicit smaller image if violated.

**Functions** (in `lexmin.cpp`, with a Python wrapper in `lexmin.py`):
- **`is_lexmin(M)`** is exact.
  - It fixes which row becomes the top row and then builds the rest row by row, refining a partition of the columns and backtracking on ties.
  - It prunes with the matrix's own automorphisms found during the search, which is the stabilizer-chain idea applied to the automorphism group rather than to G.
- **`refuted(prefix, n)`** is a fast test that is sound.
  - It returns true only when a group element makes every completion strictly smaller, so it never discards a viable prefix.
  - It is not complete: 57 non-viable prefixes passed it across the small cases I tested. Example: m=2, n=3, prefix `000 01`, where both completions are excluded but by different group elements.
- **`can_extend(prefix, m, n)`** and **`next_values(prefix, m, n)`** are exact.
  - They complete the prefix depth-first, pruned by `refuted`, and confirm the leaf with the exact test.
  - `next_values` returns which of 0 and 1 can be appended.

**Verification.**
- `is_lexmin` matched "equals the minimum of its orbit" for every matrix in the cases with mn ≤ 20 that I ran.
- `can_extend` matched brute force on every prefix of every length for mn ≤ 16, with 0 mismatches.
- `refuted` never refuted a viable prefix.
- Orderly generation using `refuted` for pruning and `is_lexmin` at the leaves reproduced the Burnside orbit counts exactly. For example (7,8) gives 53,775, (7,9) gives 355,773 and (8,9) gives 8,225,529. About 3% of nodes are dead ends, and generation takes roughly 5 µs per node.

**Caveats.**
- The search can blow up on matrices with very large automorphism groups whose symmetry only shows up late. A 15×16 Hadamard-derived matrix took about 0.03 s, but one `can_extend` query at 15×16 whose completion builds a Sylvester–Hadamard matrix took about 13 s.
- For generation, I'd use `refuted` as the pruning predicate and `is_lexmin` at the leaves, and use `can_extend` only when you need the exact yes/no.

Query
-----
Can you amplify your orbit_count_derivation.md by explaining, Part 1,
precisely what you mean by a row cycle and a column cycle, and then
explaining in detail what you mean by the constraint graph.

Answer
------
I rewrote Part 1 of `orbit_count_derivation.md` into five subsections that define row and column cycles and the constraint graph. I checked the worked example by brute force: summing the fixed-point count over all 2⁹ pairs (a,b) gives 4096, which matches the formula.

- **1.1 Row and column cycles.** A row cycle is an orbit of the row permutation σ acting on the row indices, and a column cycle is an orbit of the column permutation τ. Fixed indices count as cycles of length 1. The section also defines the cycle types λ and μ and the parity A_C or B_D (how many complemented rows or columns lie on the cycle, mod 2). One running example is used throughout, with m=5, σ=(0 1 2)(3 4) and n=4, τ=(0 1)(2)(3).
- **1.2 Cell orbits.** It shows why each block C×D splits into gcd(p,q) cell orbits of length lcm(p,q). It then derives the consistency condition (q/g)A_C + (p/g)B_D ≡ 0 (mod 2), where p and q are the cycle lengths and g = gcd(p,q).
- **1.3 The three cases.** It compares the powers of 2 dividing p and q, giving the equations A_C = B_D, B_D = 0, or A_C = 0.
- **1.4 The constraint graph.** The graph has one vertex per row cycle, one per column cycle, and one extra vertex Z standing for the constant 0. Each pair (C,D) contributes exactly one edge, of type C—D, D—Z or C—Z according to the three cases. A parity pattern is valid exactly when it is constant on every connected component and 0 on Z's component, so N(λ,μ) = 2^{(#components) − 1}. The section also explains how the graph splits by 2-adic level and gives the closed-form product that `n_parity_patterns` implements. The worked example has components {Z, D₁, C₂} and {C₁, D₂, D₃}, so N = 2.
- **1.5 From fixed points to the orbit count.** This step was previously only implied. It covers why each parity pattern is realised by 2^{m−c(σ)+n−c(τ)} pairs (a,b), and how the class sizes m!/z_λ and n!/z_μ combine into the final formula.

Section 1 was the only part I rewrote. I also confirmed the code still returns 1 for m=n=1 and 12 for m=n=4.
